# плейлист skmate

Автообновляемый плейлист автора: файлы `.m3u` / `.m3u8` приходят в Telegram-бота, сервис склеивает их в один
плейлист, проверяет каналы в фоне и отдаёт только рабочие по одной ссылке. Приложение только скачивает
готовый плейлист и ничего не проверяет.

## как работает

- одинаковые каналы (по `tvg-id`, без него по названию) склеиваются в один, все их ссылки остаются запасными,
  первой идёт ссылка из самого нового файла
- ссылка отключается после 3 неудачных проверок подряд, между проверками не меньше 10 минут
- пока основная ссылка недоступна, канал идёт по запасной, на том же месте и под тем же номером
- отключённые ссылки проверяются раз в 12 часов и возвращаются сами
- рабочие ссылки проверяются раз в 6 часов, по 12 одновременно
- порядок каналов постоянный: новые встают в конец, старые не сдвигаются

## бот

Принимает файлы только от id из `SKMATE_PL_ADMINS`, остальным не отвечает.

- файл `.m3u` / `.m3u8` — добавить каналы
- `/status` — сколько работает
- `/files` — список файлов
- `/delete N` — убрать файл

Каждый день в 9:00 присылает сводку.

## сервер

- сервер `nutrok`, папка `/opt/skmate-playlist`, данные в `/opt/skmate-playlist/data`
- процесс pm2 `skmate-playlist`, порт `127.0.0.1:18110`
- настройки в `/root/secrets/skmate-playlist/env` (права 600, не в git): `SKMATE_PL_TOKEN`, `SKMATE_PL_ADMINS`
- адреса: `/playlist.m3u8` (плейлист), `/health` (сводка)
- снаружи: `https://nutrokstore.xyz/skmate/playlist.m3u8` (блок `location` в nginx-конфиге `nutrokstore`, бэкапы в `/root/backups-nginx/`)
- бот: `@skmate_playlist_bot`

Обновить код:

```sh
scp tools/playlist-server/skmate_playlist.py tools/playlist-server/start.sh nutrok:/opt/skmate-playlist/
ssh nutrok 'pm2 restart skmate-playlist'
```
